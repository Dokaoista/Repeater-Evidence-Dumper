# Repeater Evidence Dumper

[English](README.md) · [Português (BR)](README.pt-BR.md) · [Español](README.es.md) · [简体中文](README.zh-CN.md) · **Русский** · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md)

Расширение для Burp Suite, которое превращает каждый *Send* в Repeater в готовый
для отчёта скриншот с доказательством: в оформлении интерфейса Burp и с уже
скрытыми секретами.

![Пример вывода](samples/demo.png)

Сбор доказательств для отчёта по bug bounty или пентесту обычно делается
вручную: снять скриншот окна Burp, обрезать, замазать cookie, и так для каждого
запроса. Здесь весь цикл автоматизирован. Вы отправляете запрос в Repeater, и
PNG появляется сам.

## Как это работает

Три части, связанные одним каталогом:

```
Burp Repeater ──(каждый Send)──▶ ~/burp-evidence/inbox/*.request.txt
                                                      *.response.txt
                                         │
                            watch.sh (опрос раз в 3с)
                                         │
                                    shot.mjs  ──▶ HTML в теме Burp
                                         │        └▶ headless-браузер (--screenshot)
                                         │             └▶ crop.py (обрезка + пометка)
                                         ▼
                                 ~/burp-evidence/out/*.png
```

1. **`extension/`** это Java-расширение (Montoya API). Оно регистрирует
   `HttpHandler`, который записывает в виде сырого текста каждую пару
   запрос/ответ, пришедшую из Repeater.
2. **`watch.sh`** следит за `inbox/` и отрисовывает каждую новую пару. Он
   никогда не перезаписывает уже существующий PNG, который считается
   просмотренным, и отмечает сбои в `.failed/`, чтобы не повторять попытки по
   кругу.
3. **`shot.mjs`** собирает HTML-страницу, повторяющую вид Burp (панели Request и
   Response, нумерация строк, подсветка JSON), и фотографирует её
   headless-браузером. `crop.py` ограничивает высоту и добавляет полосу с
   предупреждением, чтобы обрезка никогда не прошла незаметно.

## Требования

| Компонент | Для чего нужен |
|---|---|
| Burp Suite (Montoya API 2025.5) | само расширение |
| Java 17+ | сборка расширения |
| Node.js | `shot.mjs` (без внешних зависимостей) |
| Python 3 + [Pillow](https://pypi.org/project/Pillow/) | `crop.py` (обрезка по высоте) |
| Chrome/Chromium/Edge/Vivaldi, Firefox или Brave | отрисовка скриншота |

Рендерер пробует эти браузеры в указанном порядке и берёт первый работающий.
Пути прописаны для macOS. На другой ОС поправьте константы `CHROMIUM`,
`FIREFOX` и `BRAVE` в начале `shot.mjs`.

## Сборка

```bash
cd extension
./gradlew build
```

Jar появится в `extension/build/libs/repeater-evidence-dumper.jar`. Montoya API
объявлена как `compileOnly`, поэтому её предоставляет сам classloader Burp во
время выполнения, и в jar она не попадает.

Не хотите собирать? Возьмите готовый jar на странице
[Releases](../../releases).

## Установка

1. **Burp** → *Extensions* → *Add* → тип *Java* → выберите jar.
   В логе должно появиться `Repeater Evidence Dumper loaded`.
2. Скопируйте три скрипта в рабочий каталог:

```bash
mkdir -p ~/burp-evidence && cp shot.mjs crop.py watch.sh ~/burp-evidence/
```

3. Запустите наблюдатель:

```bash
cd ~/burp-evidence && ./watch.sh &
```

> Путь `~/burp-evidence/` зашит в коде: расширение пишет в
> `$HOME/burp-evidence/inbox`, а `watch.sh` ожидает `shot.mjs` рядом с собой.
> Чтобы изменить его, поправьте константу `INBOX` в Java-коде и `HOME_DIR` в
> `watch.sh`.

## Использование

**Автоматически.** Любой *Send* в Repeater записывает пару, а наблюдатель
отрисовывает её в `~/burp-evidence/out/`. Имя складывается из id сообщения,
метода и пути:

```
00042-post-api-activity-categories.png
```

**Вручную.** Правый клик внутри редактора запроса/ответа во вкладке Repeater и
пункт **"Dump Repeater tab now (evidence)"**. Полезно, когда вкладка ещё не
отправлена, тогда сохраняется только запрос, или когда нужен разовый снимок.
Такие файлы называются `manual-00001-...`.

**Отдельно.** Рендерер работает сам по себе над любой парой файлов:

```bash
node shot.mjs --request req.txt --response resp.txt --out evidence.png
```

## Скрытие секретов

Включено по умолчанию. У перечисленных ниже заголовков значение заменяется на
`<REDACTED>` до любой отрисовки:

`Cookie` · `Set-Cookie` · `Authorization` · `Proxy-Authorization` ·
`X-CSRF-Token` · `X-XSRF-Token` · `X-Auth-Token`

У cookie сохраняется **имя** каждой пары, а скрывается только значение
(`app.sid=<REDACTED>`), благодаря чему доказательство остаётся читаемым. Видно,
что сессия была, но сама сессия не раскрыта. В `Authorization` сохраняется схема
(`Bearer <REDACTED>`).

`--no-redact` отключает это. Не используйте флаг для доказательств, которые
пойдут в отчёт.

## Параметры `shot.mjs`

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--request <файл>` | обязателен | файл запроса |
| `--response <файл>` | нет | файл ответа |
| `--out <файл.png>` | обязателен | выходной PNG |
| `--width <px>` | `2000` | ширина изображения |
| `--scale <n>` | `1` | масштаб устройства (для retina ставьте `2`) |
| `--max-height <px>` | `420` | максимальная высота; сверх неё обрезка с пометкой. `0` отключает |
| `--all-headers` | выключено | показывать все заголовки, а не только существенные |
| `--no-redact` | выключено | отключить скрытие секретов |
| `--input <spec.json>` | нет | читать параметры из JSON вместо командной строки |

По умолчанию отрисовываются только значимые для отчёта заголовки (`Host`,
`Content-Type`, `Cookie`, `Location`, `Origin`, `Referer` и некоторые другие), и
указывается, сколько было опущено. Тело длиннее 300 строк обрезается с указанием
общего числа строк и байт. В обоих случаях пометка видна на изображении, а сырой
`.txt` в `inbox/` по-прежнему содержит всё целиком.

Формат `--input`:

```json
{
  "request_file": "req.txt",
  "response_file": "resp.txt",
  "out": "evidence.png",
  "width": 2000,
  "scale": 1,
  "redact": true
}
```

## Известное ограничение

Montoya API 2025.5 не даёт способа перечислить открытые вкладки Repeater или
прочитать текущее состояние вкладки. В пакете `burp.api.montoya.repeater` есть
только `Repeater.sendToRepeater(...)`. Поэтому захват построен на событиях и
срабатывает при каждом реальном *Send*, а не читает состояние вкладок пассивно.

На практике для получения доказательств это равноценно или даже лучше, так как
задержки нет. Но это значит, что вкладка, которую составили и ни разу не
отправили, снимается только через пункт ручного меню.
